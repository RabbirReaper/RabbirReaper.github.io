# AI 的起點 Perceptron

# 甚麼是 Artificial Intelligence

一個能夠像人一樣判斷做決定的機器。

# 該如何讓機器判斷

人類看到資料，很容易判斷「這是 A 類，那是 B 類」。但如果要讓機器做同樣的事，機器一開始什麼都不知道，必須有一套方法讓它自己慢慢調整、找到答案。這就是這個主題要解決的核心問題：機器要怎麼從「亂猜」進步到「猜對」？

最早的起源是利用 Perceptron（感知機） 。

# Perceptron（感知機）是什麼？

Perceptron 是模仿生物神經細胞的最早期數學模型。

  • 生物神經細胞會接收前端訊號，整合後決定要不要往下傳遞。
  • Perceptron 把這個過程簡化成：輸入（X）× 權重（W）相加，再加上一個門檻值（Bias, B）。

數學式：

S = W·X + B
S = W1·X1 + W2·X2 + B

判斷方式：

  • 把一個點代入這條直線方程式
  • 結果 > 0 → 在直線上方（屬於某一類）
  • 結果 < 0 → 在直線下方（屬於另一類）

W 控制直線的傾斜角度，B 控制直線的上下位置。

這其實就是國高中學過的「點斜式直線方程式」。所以 Perceptron 的本質，就是在嘗試找出一條最適合的直線（或超平面），把兩類資料分開。

如果參數超過一個，就無法在二維平面上畫出線條，可以想像每個參數都有對應的權重，然後根據實際狀況帶入數值，最後得出 S ，然後再根據 S 是否大於小於 0 來判斷。

# 如何讓 Perceptron 判斷更準確

因為機器一開始的 W、B 是隨機初始化的，那條「直線」幾乎不可能一開始就是對的。所以我們需要一個機制，讓機器看到自己的猜測距離正確答案有多遠，然後据此修正 —— 這就是 Training（訓練）的目的。

# Training（訓練） 在做什麼

讓機器看到自己的猜測距離正確答案有多遠，然後据此修正

距離正確答案有多遠，我們稱為 誤差（Error / Loss）。常見計算方式：

  • MSE（均方誤差）：(預測值 − 真實值)² 取平均
  • RMSE：MSE 再開根號

這個誤差函式也叫 目標函式（Objective Function）—— 因為我們的目標就是讓輸出盡量逼近這個函式所定義的標準答案。

# 為什麼 Perceptron 需要被「升級」成 Sigmoid 神經元？

# Perceptron 遇到的問題

Perceptron 原始使用的是 Step Function（階梯函式）：超過門檻輸出 1，否則輸出 0。Step Function 是不可微分的，沒辦法用微分去計算「我該往哪個方向調整參數」。

而我們要更新參數，勢必需要知道「調整這個參數，誤差會變大還是變小」—— 這正是微分（梯度）告訴我們的事。所以實務上會把 Step Function 換成 Sigmoid Function（可微分、輸出壓縮在 0~1 之間）。

一開始只會得出 1 或是 0，算出的 S 大於 0 或是小於 0，不會知道占比，像是大於 0 多少，小於 0 多少
可能會想說，S 算出來是友值的為什麼不用 S 判斷
因為 S 是沒有範圍的，所以你沒辦法用 S 的大小來判斷「模型有多確定」，因為每個 S 的「確定程度」差很多，卻沒有一個統一的標準來衡量。

# Sigmoid Function 在做什麼

Sigmoid 就是把這個「沒有範圍的 S」，壓縮成一個有意義的範圍 0~1：

不管 S 多大或多小
→ 輸出永遠在 0~1 之間
→ 可以直接解讀成機率
→ 才能計算出有意義的 Loss
→ 才能微分調整 W

所以 Sigmoid 解決的根本問題就是：給 S 一個統一的衡量標準。

我們要更新參數，勢必需要知道「調整這個參數，誤差會變大還是變小」—— 這正是微分（梯度）告訴我們的事。

換成 Sigmoid 之後，這個元件才正式被稱為 Neuron（神經元），而不再叫 Perceptron。

# 梯度下降（Gradient Descent）是甚麼

梯度下降就是「找 Loss 最低點」的方法。

想像一個山谷的地形，你站在某個位置，想走到最低點：

高度 = Loss
你的位置 = 目前的 W

梯度就是你腳下地面的坡度，告訴你：

往左是上坡還是下坡
往右是上坡還是下坡

下降就是每次都往下坡的方向走一步。

重複這個動作：

1. 站在某個位置（目前的 W）
2. 感受腳下的坡度（對 W 微分）
3. 往下坡方向走一步（更新 W）
4. 重複，直到走到最低點（Loss 最小）

用公式表示就是：

W_new = W_old - 學習率 × 坡度

減掉坡度，就是確保每次都往低處走。

所以梯度下降的本質就是：

用坡度當導航，一步一步把 W 調整到讓 Loss 最小的位置

# 梯度下降（Gradient Descent）實作原理

# 第一步

我們有：

W, B → 算出 S → Sigmoid(S) → 輸出 Ŷ

Loss 就是輸出跟正確答案的差距：

Loss = (正確答案 Y - 模型輸出 Ŷ)²

# 對 W 微分，得到斜率

斜率 = dLoss/dW

這個斜率告訴你：

斜率 > 0 → W 越大，Loss 越大（W 要調小）
斜率 < 0 → W 越大，Loss 越小（W 要調大）

# 為什麼要往反方向走？

帶入數字來看：

假設目前 W = 2，斜率 = 3（正的）
代表 W 再變大，Loss 會更大
所以 W 要往反方向走 → 變小

假設目前 W = 2，斜率 = -3（負的）
代表 W 再變大，Loss 會變小
所以 W 繼續往這個方向走 → 變大

兩種情況「減掉斜率」都能自動處理：

W = 2 - (+3) = -1  （變小）
W = 2 - (-3) = 5   （變大）

# 更新 W 和 B 的公式

W_new = W_old - 學習率 × 斜率
B_new = B_old - 學習率 × 斜率

學習率控制每次走多大步：

學習率太大 → 可能跳過最低點
學習率太小 → 走得太慢

# 目前遇到的問題

學到這個，我們學會了如何判斷，如何畫一條線，但是有種問題叫做 XOR 問題

XOR 問題的核心是：

一條直線沒辦法把資料分開

# 先看一個「一條線就是分不開」的例子

直覺上會想：那就多加幾個特徵不就好了？但問題不在特徵夠不夠多，而在於特徵之間的關係。有一種關係，是一條線天生處理不了的。

舉個生活化的例子：一杯飲料好不好喝，取決於加不加糖和加不加鹽這兩個特徵：

不加糖、不加鹽 → 難喝（沒味道）
   加糖、  加鹽 → 難喝（又甜又鹹，衝突）
   加糖、不加鹽 → 好喝
不加糖、  加鹽 → 好喝（例如鹽味咖啡）

規則很清楚：兩個「一樣」（都加或都不加）就難喝，兩個「不一樣」就好喝。 這就是 XOR。

現在讓那個「平的計分板」（一條線）用固定的加減分來判斷「好喝」，它會陷入死結：

  • 如果把「加糖」加分 → 「加糖加鹽」分數高了，但它其實是難喝的。
  • 如果把「加鹽」加分 → 「加鹽加糖」又更高了，一樣搞錯。
  • 想把「加鹽」扣分來救？那「只加鹽」的鹽味咖啡（好喝）也被冤枉扣分了。

不管權重怎麼調，只要它對「加糖」「加鹽」各自是固定加分或固定扣分，就永遠無法表達「加鹽好不好，得看有沒有同時加糖」這種條件式關係。這正是一條線在 XOR 上分不開的根本原因。

# 問題解釋

有一個非常著名的數學定理 —— 卡佛定理（Cover's Theorem）。

這個定理的大意是：「只要把資料丟進足夠高維度的空間裡，原本分不開的資料，幾乎都能用一條直線（超平面）完美切開。」

用剛才的 XOR 還有「特徵組合」來做個數學實測，來證實為甚麼可以，以及為什麼實際工程上大家不這麼做。

# 數學證明：是可以的

我們來看最純粹的 XOR 問題。原本只有兩個特徵 A 和 B （數值只有 0 或 1）：

(0, 0) → 輸出 0
(1, 1) → 輸出 0
(1, 0) → 輸出 1
(0, 1) → 輸出 1

先說明這裡的參數是什麼：

  • A 、 B ：兩個原始特徵，各自只有 0 或 1 兩種值（可以想成「開關」）。
  • 輸出：這組特徵對應的正確答案（標籤）。XOR 的規則是「兩個一樣 → 0，兩個不一樣 → 1」。

在二維平面上，這四個點無法用一條直線把 0 和 1 分開（這就是 XOR 分不開的原因）。

接著加入新參數 C ：

C 是手動創造出來的新特徵，定義成 C = A × B （把 A 和 B 相乘）。它不是新資料，而是從既有特徵「組合」出來的。加了 C 之後，每筆資料就從兩個維度 (A, B) 變成三個維度 (A, B, C) ：

原來的 (0, 0) 變成 (0, 0, 0) → 輸出 0
原來的 (1, 1) 變成 (1, 1, 1) → 輸出 0
原來的 (1, 0) 變成 (1, 0, 0) → 輸出 1
原來的 (0, 1) 變成 (0, 1, 0) → 輸出 1

C 的作用：只有在 A 和 B 同時為 1 時 C 才會是 1，其餘情況都是 0。等於是用 C 幫「兩個都成立」這個特殊狀況做了一個獨立的標記。

下面這段例子，是要證明「加了 C 之後，原本畫不出的線，現在畫得出來了」。

升到三維後，就能只靠一個神經元（一條線）解決。這個神經元的計分規則可以設計成：

總分 = A + B - 2C （總分大於 0.5 判為 1，否則判為 0）

把四筆資料都代入這條規則驗算：

(0, 0, 0) → 0 + 0 - 0 = 0  （小於 0.5 → 判為 0，正確）
(1, 1, 1) → 1 + 1 - 2 = 0  （小於 0.5 → 判為 0，正確）
(1, 0, 0) → 1 + 0 - 0 = 1  （大於 0.5 → 判為 1，正確）
(0, 1, 0) → 0 + 1 - 0 = 1  （大於 0.5 → 判為 1，正確）

四筆資料套用同一條規則全部判斷正確，代表這條線真的把 0 和 1 分開了。

回頭呼應前面「加糖加鹽」的例子：

前面那杯飲料就是這個 XOR 的具象版。把 A = 加糖 、 B = 加鹽 、輸出 1 = 好喝 對應回去，四筆資料完全一致：

不加糖、不加鹽 → (0, 0) → 難喝(0)
   加糖、  加鹽 → (1, 1) → 難喝(0)
   加糖、不加鹽 → (1, 0) → 好喝(1)
不加糖、  加鹽 → (0, 1) → 好喝(1)

之前計分板卡關，是因為它對「加糖」「加鹽」只能各自固定加減分，沒辦法判斷「加鹽好不好，要看有沒有同時加糖」。而 C = A × B （加糖 且 加鹽）這個組合特徵，正好標記出「兩個都加」這個唯一會出問題的狀況 —— 四筆裡只有「加糖加鹽」的 C 是 1。於是計分規則 A + B - 2C 就能靠 -2C 精準地把「又甜又鹹」這杯壓成難喝，同時完全不影響其他三杯。這就是為什麼加了 C 之後，原本卡關的判斷現在解得開了 —— 組合特徵幫線性計分板補上了它缺的「條件式判斷」能力。

結論： 只要增加像 C 這種「乘在一起」的組合參數，把資料升到更高維度，原本一條直線分不開的非線性問題，就變得可以用一條直線解決。

# 那為什麼「實際上無法」這麼做？

既然理論上可行，為什麼科學家最後放棄了這個路線，轉去研究「多層神經網路」？因為現實生活中的「狗」，會讓參數數量產生維度災難（Curse of Dimensionality）。

假設我們判斷一隻狗，手頭上有 100 個基本特徵（眼睛、鼻子、毛色、腿長、耳朵形狀…… 等等）。

如果我們要像上面一樣，把所有可能「兩兩相乘」的組合參數都列出來：

  • 眼睛 * 鼻子 、 眼睛 * 毛色 、 腿長 * 耳朵 ……
  • 光是兩兩組合，就會產生將近 5,000 個新參數。

但如果只乘兩個不夠呢？萬一真實的狗需要三個特徵同時成立（例如： 黃色 * 體型大 * 垂耳 才是黃金獵犬），我們要列出三個相乘的組合：

  • 這會產生將近 16 萬個新參數。

如果要四個相乘、五個相乘呢？參數總數會呈指數級暴增，變成幾百萬、幾千萬個。

實際上的困境：

  1. 記憶體與計算量爆炸： 電腦根本吃不消。
  2. 我們根本不知道該列哪些： 也許狗的真正秘密是 特徵3 * 特徵28 * 特徵99 ，但我們漏列了，那這條線就永遠畫不出來。
  3. 流氓科學（過擬合）： 當參數比資料點還多的時候，這條線確實能完美分開現有的資料，但只要來一隻稍微不一樣的狗，它就會完全猜錯。

# 多層神經網路，是怎麼優雅解決這個問題的？

多層神經網路（深度學習）的精妙之處，就在於它不搞「一次列出所有組合」這種暴力破解。

它採取的是「層層遞進」的結構：

  • 第一層（只做簡單組合）：神經元 A 負責把 黃色 和 體型大 加在一起；神經元 B 負責把 垂耳 和 長尾巴 加在一起。
  • 第二層（把第一層的結果再組合）：神經元 C 只需要把（神經元 A 的結果）和（神經元 B 的結果）加在一起。

這樣做，參數的數量是線性增加的（可能只要幾百個），而不是指數暴增（幾千萬個）。它利用「疊豆腐」的方式，用少量的參數，就達到了和幾千萬個組合參數一樣強大的表達能力。

所以整體結論是：
理論上，列出所有組合參數，確實可以用一條直線解決非線性問題；但實際上，因為組合太多、人類無法預知，所以改用「多層神經網路」讓電腦自己去層層組合。

這就是「多層」這個概念存在的理由。

# 神經網路的完整訓練流程：前傳遞、倒傳遞、資料集、Overfitting

# 出發點：有了多層神經元，要怎麼讓「整個網路」一起學習？

上一個主題解決了「一個神經元怎麼學」，但 XOR 問題告訴我們，真實世界的問題往往需要多層、多個神經元合作。那麼問題來了：資料怎麼流過這麼多層？又該怎麼一次更新「所有」神經元的參數？這就是本篇要解決的核心問題。

# 神經網路是什麼？

神經網路（Neural Network）由三個主要部分組成：

  • 輸入層：負責把資料餵進去
  • 隱藏層：負責做特徵的整理與轉換（Feature Transform），可以有很多層
  • 輸出層：負責把整理好的特徵轉換成最終答案

一個關鍵原則：神經網路只接受數值化的輸入與輸出。所以圖片、聲音、文字都必須先想辦法轉換成數字（後面在 CNN、NLP 主題會分別講怎麼做）。

# 為什麼隱藏層要「模組化分工」？

可以把隱藏層想成寫程式時拆出來的子程式：每一層只負責處理一小部分任務，而不是用一顆超大函式硬解決所有事情。

舉影像分類為例：

  • 第一層可能只負責偵測「有沒有特定顏色」
  • 第二層可能負責偵測「紋路」（石頭紋、木頭紋…）
  • 最後幾層才綜合判斷「這是輪胎還是人」

這種漸進式抽象正是深度學習能處理複雜問題的關鍵，也是為什麼網路需要疊很多層（deep）。

# 前傳遞（Forward Propagation）實作原理

前傳遞就是資料「正向」流過整個網路的過程：

  1. 輸入資料（例如圖片，需要先展平 flatten 成一維向量）
  2. 第一層：輸入 × 權重相加，丟進啟用函式，得到輸出 Ŷ
  3. 把這個 Ŷ 當作下一層的輸入，重複這個過程
  4. 一直到輸出層 —— 但輸出層的啟用函式通常不是 Sigmoid，而是 Softmax（把輸出轉成各類別的機率分布）

簡單說：前傳遞 = 從輸入一路往前算到輸出。

# 為什麼需要倒傳遞（Backpropagation）？

前傳遞只負責「算出答案」，但這個答案一開始一定是錯的。我們需要一個方法，把這個錯誤「歸因」回每一層、每一個參數，才知道該怎麼修正 —— 這就是倒傳遞要做的事。

倒傳遞的方向，恰好與前傳遞相反：先算出輸出層的誤差，再用梯度，從輸出層往回一層一層更新隱藏層，直到輸入層為止。本質上用的公式跟單一神經元的梯度下降是一樣的，只是規模擴大到整個網路。

一筆資料完整跑完一次前傳遞 + 倒傳遞，這次更新才算結束，接著才會輸入下一筆資料繼續訓練。

# 為什麼 Sigmoid 會造成梯度消失／爆炸？

Sigmoid 的特性是把輸入壓縮到 0~1 之間。倒傳遞時需要連鎖律不斷把各層的微分值「相乘」，而 Sigmoid 的微分值本身就偏小（最大也只有 0.25），連續相乘很多層之後，數值會越乘越小，最終趨近於 0 —— 這就是梯度消失，會導致前面幾層幾乎學不到東西。

改用 ReLU 是常見解法：正值區間是線性輸出（不會被壓縮），能有效緩解梯度消失。雖然 ReLU 在輸入小於 0 時「不可微分」，但因為那個區域剛好輸出是 0（代表這個神經元不會更新），所以實務上不需要太擔心這個不可微分點。

# 資料集（Dataset）的設計原理

# 為什麼資料集要「有意義」？

模型學到的東西，完全取決於餵給它的資料。如果你要做「貓 vs 狗」分類器：

  • 貓與狗的照片數量不能差太多（類別要平衡）
  • 不相關的照片（如駱駝、馬）數量也不能超過目標類別

一般經驗上，資料量至少要達到上千筆以上才稱得上是一個夠用的資料集，實務上百萬級的資料集效果通常更好。

# 資料集的切分

  • 訓練資料集（Training Set）：用來實際訓練模型
  • 驗證資料集（Validation Set）：像「隨堂小考」，訓練過程中檢查模型是否往對的方向發展
  • 測試資料集（Test Set）：像「期末考」，訓練完成後才拿出來最終評估

# 為什麼需要不同的訓練方式（Batch / Mini-batch / SGD）？

理論上應該讓模型「看完全部資料」再更新一次參數最穩定，但現實中記憶體（GPU 顯存）容量有限，無法一次塞進全部資料，所以衍生出三種策略：

方法 做法 特性
Batch（BGD） 一次用全部資料訓練一次 路徑平穩，但記憶體需求最大
Mini-batch（MGD） 切成固定大小的小批次（如一次 3 筆）訓練 介於兩者之間，最常用於兼顧記憶體與效果
隨機梯度下降（SGD） 每次只隨機抓 1 筆資料訓練 路徑震盪（看起來很亂），但運算快、最終仍會收斂，目前最常用

完整跑完一次「全部資料集」（不論用哪種切分方式），就稱為一個 Epoch（世代）。

# Overfitting（過擬合）是什麼？為什麼會發生？

理想狀態下，模型應該學到資料背後的「規律」（一條能大致貼合所有資料趨勢的曲線）。

但如果訓練次數太多或資料集太小，模型會開始「死記」訓練資料的答案，而不是學習規律 —— 這就是 Overfitting。

後果：模型在訓練資料上表現很好，但換一批稍有差異的測試資料，準確度就會明顯下滑。

這個概念在後面 CNN 主題會延伸出具體解法（如 Data Augmentation 資料增強）。

# 銜接下一步

現在我們已經知道神經網路「理論上」怎麼運作，但實際動手刻一個多層網路、手動算每一層的梯度，工程上非常繁瑣。下一個主題會介紹深度學習框架，看它怎麼幫我們自動完成這整套流程。
