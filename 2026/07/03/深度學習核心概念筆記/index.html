# AI 的起點 Perceptron

# 甚麼是 Artificial Intelligence

一個能夠像人一樣判斷做決定的機器。

# 該如何讓機器判斷

人類看到資料，很容易判斷「這是 A 類，那是 B 類」。但如果要讓機器做同樣的事，機器一開始什麼都不知道，必須有一套方法讓它自己慢慢調整、找到答案。這就是這個主題要解決的核心問題：機器要怎麼從「亂猜」進步到「猜對」？

最早的起源是利用 Perceptron（感知機） 。

# Perceptron（感知機）是什麼？

Perceptron 是模仿生物神經細胞的最早期數學模型。

  • 生物神經細胞會接收前端訊號，整合後決定要不要往下傳遞。
  • Perceptron 把這個過程簡化成：輸入（X）× 權重（W）相加，再加上一個門檻值（Bias, B）。

數學式：

S = W·X + B
S = W1·X1 + W2·X2 + B

判斷方式：

  • 把一個點代入這條直線方程式
  • 結果 > 0 → 在直線上方（屬於某一類）
  • 結果 < 0 → 在直線下方（屬於另一類）

W 控制直線的傾斜角度，B 控制直線的上下位置。

這其實就是國高中學過的「點斜式直線方程式」。所以 Perceptron 的本質，就是在嘗試找出一條最適合的直線（或超平面），把兩類資料分開。

如果參數超過一個，就無法在二維平面上畫出線條，可以想像每個參數都有對應的權重，然後根據實際狀況帶入數值，最後得出 S ，然後再根據 S 是否大於小於 0 來判斷。

# 如何讓 Perceptron 判斷更準確

因為機器一開始的 W、B 是隨機初始化的，那條「直線」幾乎不可能一開始就是對的。所以我們需要一個機制，讓機器看到自己的猜測距離正確答案有多遠，然後据此修正 —— 這就是 Training（訓練）的目的。

# Training（訓練） 在做什麼

讓機器看到自己的猜測距離正確答案有多遠，然後据此修正

距離正確答案有多遠，我們稱為 誤差（Error / Loss）。常見計算方式：

  • MSE（均方誤差）：(預測值 − 真實值)² 取平均
  • RMSE：MSE 再開根號

這個誤差函式也叫 目標函式（Objective Function）—— 因為我們的目標就是讓輸出盡量逼近這個函式所定義的標準答案。

# 為什麼 Perceptron 需要被「升級」成 Sigmoid 神經元？

# Perceptron 遇到的問題

Perceptron 原始使用的是 Step Function（階梯函式）：超過門檻輸出 1，否則輸出 0。Step Function 是不可微分的，沒辦法用微分去計算「我該往哪個方向調整參數」。

而我們要更新參數，勢必需要知道「調整這個參數，誤差會變大還是變小」—— 這正是微分（梯度）告訴我們的事。所以實務上會把 Step Function 換成 Sigmoid Function（可微分、輸出壓縮在 0~1 之間）。

一開始只會得出 1 或是 0，算出的 S 大於 0 或是小於 0，不會知道占比，像是大於 0 多少，小於 0 多少
可能會想說，S 算出來是友值的為什麼不用 S 判斷
因為 S 是沒有範圍的，所以你沒辦法用 S 的大小來判斷「模型有多確定」，因為每個 S 的「確定程度」差很多，卻沒有一個統一的標準來衡量。

# Sigmoid Function 在做什麼

Sigmoid 就是把這個「沒有範圍的 S」，壓縮成一個有意義的範圍 0~1：

不管 S 多大或多小
→ 輸出永遠在 0~1 之間
→ 可以直接解讀成機率
→ 才能計算出有意義的 Loss
→ 才能微分調整 W

所以 Sigmoid 解決的根本問題就是：給 S 一個統一的衡量標準。

我們要更新參數，勢必需要知道「調整這個參數，誤差會變大還是變小」—— 這正是微分（梯度）告訴我們的事。

換成 Sigmoid 之後，這個元件才正式被稱為 Neuron（神經元），而不再叫 Perceptron。

# 梯度下降（Gradient Descent）是甚麼

梯度下降就是「找 Loss 最低點」的方法。

想像一個山谷的地形，你站在某個位置，想走到最低點：

高度 = Loss
你的位置 = 目前的 W

梯度就是你腳下地面的坡度，告訴你：

往左是上坡還是下坡
往右是上坡還是下坡

下降就是每次都往下坡的方向走一步。

重複這個動作：

1. 站在某個位置（目前的 W）
2. 感受腳下的坡度（對 W 微分）
3. 往下坡方向走一步（更新 W）
4. 重複，直到走到最低點（Loss 最小）

用公式表示就是：

W_new = W_old - 學習率 × 坡度

減掉坡度，就是確保每次都往低處走。

所以梯度下降的本質就是：

用坡度當導航，一步一步把 W 調整到讓 Loss 最小的位置

# 梯度下降（Gradient Descent）實作原理

# 第一步

我們有：

W, B → 算出 S → Sigmoid(S) → 輸出 Ŷ

Loss 就是輸出跟正確答案的差距：

Loss = (正確答案 Y - 模型輸出 Ŷ)²

# 對 W 微分，得到斜率

斜率 = dLoss/dW

這個斜率告訴你：

斜率 > 0 → W 越大，Loss 越大（W 要調小）
斜率 < 0 → W 越大，Loss 越小（W 要調大）

# 為什麼要往反方向走？

帶入數字來看：

假設目前 W = 2，斜率 = 3（正的）
代表 W 再變大，Loss 會更大
所以 W 要往反方向走 → 變小

假設目前 W = 2，斜率 = -3（負的）
代表 W 再變大，Loss 會變小
所以 W 繼續往這個方向走 → 變大

兩種情況「減掉斜率」都能自動處理：

W = 2 - (+3) = -1  （變小）
W = 2 - (-3) = 5   （變大）

# 更新 W 和 B 的公式

W_new = W_old - 學習率 × 斜率
B_new = B_old - 學習率 × 斜率

學習率控制每次走多大步：

學習率太大 → 可能跳過最低點
學習率太小 → 走得太慢

# 目前遇到的問題

學到這個，我們學會了如何判斷，如何畫一條線，但是有種問題叫做 XOR 問題

XOR 問題的核心是：

一條直線沒辦法把資料分開

# 先看一個「一條線就是分不開」的例子

直覺上會想：那就多加幾個特徵不就好了？但問題不在特徵夠不夠多，而在於特徵之間的關係。有一種關係，是一條線天生處理不了的。

舉個生活化的例子：一杯飲料好不好喝，取決於加不加糖和加不加鹽這兩個特徵：

不加糖、不加鹽 → 難喝（沒味道）
   加糖、  加鹽 → 難喝（又甜又鹹，衝突）
   加糖、不加鹽 → 好喝
不加糖、  加鹽 → 好喝（例如鹽味咖啡）

規則很清楚：兩個「一樣」（都加或都不加）就難喝，兩個「不一樣」就好喝。 這就是 XOR。

現在讓那個「平的計分板」（一條線）用固定的加減分來判斷「好喝」，它會陷入死結：

  • 如果把「加糖」加分 → 「加糖加鹽」分數高了，但它其實是難喝的。
  • 如果把「加鹽」加分 → 「加鹽加糖」又更高了，一樣搞錯。
  • 想把「加鹽」扣分來救？那「只加鹽」的鹽味咖啡（好喝）也被冤枉扣分了。

不管權重怎麼調，只要它對「加糖」「加鹽」各自是固定加分或固定扣分，就永遠無法表達「加鹽好不好，得看有沒有同時加糖」這種條件式關係。這正是一條線在 XOR 上分不開的根本原因。

# 問題解釋

有一個非常著名的數學定理 —— 卡佛定理（Cover's Theorem）。

這個定理的大意是：「只要把資料丟進足夠高維度的空間裡，原本分不開的資料，幾乎都能用一條直線（超平面）完美切開。」

用剛才的 XOR 還有「特徵組合」來做個數學實測，來證實為甚麼可以，以及為什麼實際工程上大家不這麼做。

# 數學證明：是可以的

我們來看最純粹的 XOR 問題。原本只有兩個特徵 A 和 B （數值只有 0 或 1）：

(0, 0) → 輸出 0
(1, 1) → 輸出 0
(1, 0) → 輸出 1
(0, 1) → 輸出 1

先說明這裡的參數是什麼：

  • A 、 B ：兩個原始特徵，各自只有 0 或 1 兩種值（可以想成「開關」）。
  • 輸出：這組特徵對應的正確答案（標籤）。XOR 的規則是「兩個一樣 → 0，兩個不一樣 → 1」。

在二維平面上，這四個點無法用一條直線把 0 和 1 分開（這就是 XOR 分不開的原因）。

接著加入新參數 C ：

C 是手動創造出來的新特徵，定義成 C = A × B （把 A 和 B 相乘）。它不是新資料，而是從既有特徵「組合」出來的。加了 C 之後，每筆資料就從兩個維度 (A, B) 變成三個維度 (A, B, C) ：

原來的 (0, 0) 變成 (0, 0, 0) → 輸出 0
原來的 (1, 1) 變成 (1, 1, 1) → 輸出 0
原來的 (1, 0) 變成 (1, 0, 0) → 輸出 1
原來的 (0, 1) 變成 (0, 1, 0) → 輸出 1

C 的作用：只有在 A 和 B 同時為 1 時 C 才會是 1，其餘情況都是 0。等於是用 C 幫「兩個都成立」這個特殊狀況做了一個獨立的標記。

下面這段例子，是要證明「加了 C 之後，原本畫不出的線，現在畫得出來了」。

升到三維後，就能只靠一個神經元（一條線）解決。這個神經元的計分規則可以設計成：

總分 = A + B - 2C （總分大於 0.5 判為 1，否則判為 0）

把四筆資料都代入這條規則驗算：

(0, 0, 0) → 0 + 0 - 0 = 0  （小於 0.5 → 判為 0，正確）
(1, 1, 1) → 1 + 1 - 2 = 0  （小於 0.5 → 判為 0，正確）
(1, 0, 0) → 1 + 0 - 0 = 1  （大於 0.5 → 判為 1，正確）
(0, 1, 0) → 0 + 1 - 0 = 1  （大於 0.5 → 判為 1，正確）

四筆資料套用同一條規則全部判斷正確，代表這條線真的把 0 和 1 分開了。

回頭呼應前面「加糖加鹽」的例子：

前面那杯飲料就是這個 XOR 的具象版。把 A = 加糖 、 B = 加鹽 、輸出 1 = 好喝 對應回去，四筆資料完全一致：

不加糖、不加鹽 → (0, 0) → 難喝(0)
   加糖、  加鹽 → (1, 1) → 難喝(0)
   加糖、不加鹽 → (1, 0) → 好喝(1)
不加糖、  加鹽 → (0, 1) → 好喝(1)

之前計分板卡關，是因為它對「加糖」「加鹽」只能各自固定加減分，沒辦法判斷「加鹽好不好，要看有沒有同時加糖」。而 C = A × B （加糖 且 加鹽）這個組合特徵，正好標記出「兩個都加」這個唯一會出問題的狀況 —— 四筆裡只有「加糖加鹽」的 C 是 1。於是計分規則 A + B - 2C 就能靠 -2C 精準地把「又甜又鹹」這杯壓成難喝，同時完全不影響其他三杯。這就是為什麼加了 C 之後，原本卡關的判斷現在解得開了 —— 組合特徵幫線性計分板補上了它缺的「條件式判斷」能力。

結論： 只要增加像 C 這種「乘在一起」的組合參數，把資料升到更高維度，原本一條直線分不開的非線性問題，就變得可以用一條直線解決。

# 那為什麼「實際上無法」這麼做？

既然理論上可行，為什麼科學家最後放棄了這個路線，轉去研究「多層神經網路」？因為現實生活中的「狗」，會讓參數數量產生維度災難（Curse of Dimensionality）。

假設我們判斷一隻狗，手頭上有 100 個基本特徵（眼睛、鼻子、毛色、腿長、耳朵形狀…… 等等）。

如果我們要像上面一樣，把所有可能「兩兩相乘」的組合參數都列出來：

  • 眼睛 * 鼻子 、 眼睛 * 毛色 、 腿長 * 耳朵 ……
  • 光是兩兩組合，就會產生將近 5,000 個新參數。

但如果只乘兩個不夠呢？萬一真實的狗需要三個特徵同時成立（例如： 黃色 * 體型大 * 垂耳 才是黃金獵犬），我們要列出三個相乘的組合：

  • 這會產生將近 16 萬個新參數。

如果要四個相乘、五個相乘呢？參數總數會呈指數級暴增，變成幾百萬、幾千萬個。

實際上的困境：

  1. 記憶體與計算量爆炸： 電腦根本吃不消。
  2. 我們根本不知道該列哪些： 也許狗的真正秘密是 特徵3 * 特徵28 * 特徵99 ，但我們漏列了，那這條線就永遠畫不出來。
  3. 流氓科學（過擬合）： 當參數比資料點還多的時候，這條線確實能完美分開現有的資料，但只要來一隻稍微不一樣的狗，它就會完全猜錯。

# 多層神經網路，是怎麼優雅解決這個問題的？

多層神經網路（深度學習）的精妙之處，就在於它不搞「一次列出所有組合」這種暴力破解。

它採取的是「層層遞進」的結構：

  • 第一層（只做簡單組合）：神經元 A 負責把 黃色 和 體型大 加在一起；神經元 B 負責把 垂耳 和 長尾巴 加在一起。
  • 第二層（把第一層的結果再組合）：神經元 C 只需要把（神經元 A 的結果）和（神經元 B 的結果）加在一起。

這樣做，參數的數量是線性增加的（可能只要幾百個），而不是指數暴增（幾千萬個）。它利用「疊豆腐」的方式，用少量的參數，就達到了和幾千萬個組合參數一樣強大的表達能力。

所以整體結論是：
理論上，列出所有組合參數，確實可以用一條直線解決非線性問題；但實際上，因為組合太多、人類無法預知，所以改用「多層神經網路」讓電腦自己去層層組合。

這就是「多層」這個概念存在的理由。

# 神經網路的完整訓練流程：前傳遞、倒傳遞、資料集、Overfitting

# 出發點：有了多層神經元，要怎麼讓「整個網路」一起學習？

上一個主題解決了「一個神經元怎麼學」，但 XOR 問題告訴我們，真實世界的問題往往需要多層、多個神經元合作。那麼問題來了：資料怎麼流過這麼多層？又該怎麼一次更新「所有」神經元的參數？這就是本篇要解決的核心問題。

# 神經網路是什麼？

神經網路（Neural Network）由三個主要部分組成：

  • 輸入層：負責把資料餵進去
  • 隱藏層：負責做特徵的整理與轉換（Feature Transform），可以有很多層
  • 輸出層：負責把整理好的特徵轉換成最終答案

一個關鍵原則：神經網路只接受數值化的輸入與輸出。所以圖片、聲音、文字都必須先想辦法轉換成數字（後面在 CNN、NLP 主題會分別講怎麼做）。

# 為什麼隱藏層要「模組化分工」？

可以把隱藏層想成寫程式時拆出來的子程式：每一層只負責處理一小部分任務，而不是用一顆超大函式硬解決所有事情。

舉影像分類為例：

  • 第一層可能只負責偵測「有沒有特定顏色」
  • 第二層可能負責偵測「紋路」（石頭紋、木頭紋…）
  • 最後幾層才綜合判斷「這是輪胎還是人」

這種漸進式抽象正是深度學習能處理複雜問題的關鍵，也是為什麼網路需要疊很多層（deep）。

# 前傳遞（Forward Propagation）實作原理

前傳遞就是資料「正向」流過整個網路的過程：

  1. 輸入資料（例如圖片，需要先展平 flatten 成一維向量）
  2. 第一層：輸入 × 權重相加，丟進啟用函式，得到輸出 Ŷ
  3. 把這個 Ŷ 當作下一層的輸入，重複這個過程
  4. 一直到輸出層 —— 但輸出層的啟用函式通常不是 Sigmoid，而是 Softmax（把輸出轉成各類別的機率分布）

簡單說：前傳遞 = 從輸入一路往前算到輸出。

# 為什麼需要倒傳遞（Backpropagation）？

前傳遞只負責「算出答案」，但這個答案一開始一定是錯的。我們需要一個方法，把這個錯誤「歸因」回每一層、每一個參數，才知道該怎麼修正 —— 這就是倒傳遞要做的事。

倒傳遞的方向，恰好與前傳遞相反：先算出輸出層的誤差，再用梯度，從輸出層往回一層一層更新隱藏層，直到輸入層為止。本質上用的公式跟單一神經元的梯度下降是一樣的，只是規模擴大到整個網路。

一筆資料完整跑完一次前傳遞 + 倒傳遞，這次更新才算結束，接著才會輸入下一筆資料繼續訓練。

# 為什麼 Sigmoid 會造成梯度消失／爆炸？

Sigmoid 的特性是把輸入壓縮到 0~1 之間。倒傳遞時需要連鎖律不斷把各層的微分值「相乘」，而 Sigmoid 的微分值本身就偏小（最大也只有 0.25），連續相乘很多層之後，數值會越乘越小，最終趨近於 0 —— 這就是梯度消失，會導致前面幾層幾乎學不到東西。

改用 ReLU 是常見解法：正值區間是線性輸出（不會被壓縮），能有效緩解梯度消失。雖然 ReLU 在輸入小於 0 時「不可微分」，但因為那個區域剛好輸出是 0（代表這個神經元不會更新），所以實務上不需要太擔心這個不可微分點。

# 資料集（Dataset）的設計原理

# 為什麼資料集要「有意義」？

模型學到的東西，完全取決於餵給它的資料。如果你要做「貓 vs 狗」分類器：

  • 貓與狗的照片數量不能差太多（類別要平衡）
  • 不相關的照片（如駱駝、馬）數量也不能超過目標類別

一般經驗上，資料量至少要達到上千筆以上才稱得上是一個夠用的資料集，實務上百萬級的資料集效果通常更好。

# 資料集的切分

  • 訓練資料集（Training Set）：用來實際訓練模型
  • 驗證資料集（Validation Set）：像「隨堂小考」，訓練過程中檢查模型是否往對的方向發展
  • 測試資料集（Test Set）：像「期末考」，訓練完成後才拿出來最終評估

# 為什麼需要不同的訓練方式（Batch / Mini-batch / SGD）？

理論上應該讓模型「看完全部資料」再更新一次參數最穩定，但現實中記憶體（GPU 顯存）容量有限，無法一次塞進全部資料，所以衍生出三種策略：

方法 做法 特性
Batch（BGD） 一次用全部資料訓練一次 路徑平穩，但記憶體需求最大
Mini-batch（MGD） 切成固定大小的小批次（如一次 3 筆）訓練 介於兩者之間，最常用於兼顧記憶體與效果
隨機梯度下降（SGD） 每次只隨機抓 1 筆資料訓練 路徑震盪（看起來很亂），但運算快、最終仍會收斂，目前最常用

完整跑完一次「全部資料集」（不論用哪種切分方式），就稱為一個 Epoch（世代）。

# Overfitting（過擬合）是什麼？為什麼會發生？

理想狀態下，模型應該學到資料背後的「規律」（一條能大致貼合所有資料趨勢的曲線）。

但如果訓練次數太多或資料集太小，模型會開始「死記」訓練資料的答案，而不是學習規律 —— 這就是 Overfitting。

後果：模型在訓練資料上表現很好，但換一批稍有差異的測試資料，準確度就會明顯下滑。

這個概念在後面 CNN 主題會延伸出具體解法（如 Data Augmentation 資料增強）。

# 深度學習框架與 PyTorch

# 出發點：理論都懂了，但自己手刻一個神經網路太痛苦

前面的主題我們已經知道神經網路的數學原理：矩陣運算、連鎖律算梯度、逐層更新參數。但如果每次設計一個新模型，都要自己手寫每一層的矩陣相乘、手算每個參數的偏微分，工程成本會非常高，而且很容易出錯。框架就是為了解決這個工程問題而存在的。

# 為什麼需要深度學習框架？

深度學習裡最重要、最核心的兩件事是：

  1. 矩陣運算：神經網路每一層的本質就是「輸入向量 × 權重矩陣 + Bias」，這正好可以用矩陣運算高效完成。
  2. 自動計算梯度（Autograd）：如果自訂一個比較複雜的神經網路架構，每次都要手算微分公式太麻煩，框架要能自動幫我們算出每個參數的梯度。

除此之外，框架還提供：

  1. GPU 加速：矩陣運算非常適合用 GPU 做平行化處理，框架幫我們處理好底層的加速。
  2. High-level API：框架內建很多現成的函式、甚至預訓練好的模型，可以直接呼叫使用，不用每次從零開始寫。

# 主流框架是什麼？—— TensorFlow vs PyTorch

# TensorFlow（Google 開發）

  • 名稱來源：Tensor（張量，本質上就是矩陣 / 向量）+ Flow（資料在張量之間流動）。
  • 1.x 版本：使用 靜態計算圖（Static Computational Graph），運作方式是 define and run—— 你必須先把整個網路結構定義完，才開一個 Session 一次性建好整個計算圖再執行。
    • 優點：因為是整個圖一次建好，執行效率較高，適合業界正式部署。
    • 缺點：除錯不方便（你無法在中間下中斷點去看某個變數當下的值，因為圖根本還沒真正建好）。
  • 2.x 版本：改用 Eager Execution（動態圖），運作方式變得跟 PyTorch 很像，並把 Keras（高階 API）整合進來。

# PyTorch（Facebook 開發，前身為 Torch）

  • 使用 動態計算圖（Dynamic Computational Graph），運作方式是 define by run—— 程式執行到哪一行，計算圖就同步建到哪裡。
    • 優點：方便除錯（可以隨時下中斷點看當下的 Tensor 長什麼樣子），更適合研究人員快速試錯。
  • 與 NumPy 高度相容，資料格式轉換方便（很多影像讀取套件如 OpenCV 讀進來的格式就是 NumPy）。

因為 TensorFlow 1.x 與 2.x 版本之間的用法落差較大，網路教學常常新舊混雜，容易造成混淆。這也是為什麼教學上通常會優先選 PyTorch 來示範。

# PyTorch 訓練流程的實作原理

# 整體 Workflow

準備資料 → 建立模型
   ↓
資料前處理
   ↓
餵進模型做預測（前傳遞）
   ↓
用 Loss Function 計算預測值與真實答案的誤差
   ↓
對每個權重 / Bias 計算梯度（loss.backward()）
   ↓
用 Optimizer 更新權重
   ↓
（重複以上步驟，稱為 Training Loop）

# 資料前處理的具體步驟

  1. 收集資料（Collect）
  2. 正規化（Normalization）/ 標準化（Standardization）
    • Normalization（Min-Max）：把每個資料點減去最小值，再除以（最大值−最小值），把數值縮放到 0~1 之間。
    • Standardization：把每個資料點減去平均值，再除以標準差，讓不同維度的「變動幅度」趨於一致。
    • 為什�麼需要這一步：如果不同維度的數值範圍差異很大（例如 X 軸是 0~1，Y 軸是 0~1000），整個誤差曲面會被拉得很扁，學習率稍大就容易在曲面上來回震盪，難以收斂。做完正規化後，誤差曲面會比較接近圓形，訓練更穩定。
    • ⚠️ 務必對 Train / Validation / Test 三份資料「同步」處理，不能各自獨立計算，否則資料分布會跑掉。
  3. 切分資料集：Training / Validation / Test
  4. 切分 Batch：資料量太大時，分批送進模型訓練（對應前一主題提到的 Mini-batch）

# 為什麼要手動把梯度「歸零」（zero_grad）？

這跟框架底層的 Computational Graph（計算圖） 機制有關：框架會把每一個運算拆解成最小單位（加、乘、平方…），這樣才能套用連鎖律的規則，自動算出每個參數的梯度。

但因為梯度是「累加」計算的（連鎖律一路往回乘加），框架沒辦法自己判斷「你想要一筆資料更新一次，還是累積一個 batch 才更新一次」，所以需要工程師自己決定何時呼叫 zero_grad() 把梯度歸零，避免梯度不小心累加到下一輪。

# 應用：一個典型的 PyTorch 訓練範例

以乳癌資料集（來自 sklearn）為例的典型流程：

  1. 用 sklearn 載入資料集
  2. 做 Normalization / Standardization
  3. 切分 Train / Validation / Test
  4. 定義模型架構（幾層、每層幾顆神經元）
  5. 定義 Loss Function（如 MSE 或 Cross Entropy）與 Optimizer（如 SGD）
  6. 寫 Training Loop：前傳遞 → 算 Loss → loss.backward() 算梯度 → Optimizer 更新權重
  7. 用 Validation Set 檢查訓練是否正常（例如畫出 Loss / Accuracy 曲線）
  8. 訓練完成後，用 Test Set 做最終評估

# 分類任務的核心元件：Encoding、Softmax、啟用 / 損失函式、Optimizer

# 出發點：模型要怎麼「理解」類別？輸出又要怎麼變成一個合理的答案？

前面我們已經能用 PyTorch 跑出一個完整的訓練流程，但中間還有幾個關鍵問題沒解決：類別標籤（如「貓」「狗」「鳥」）要怎麼變成數字？模型輸出一堆雜亂的數字，要怎麼變成「這張圖 89% 像狗」這種合理的機率？還有，Optimizer 除了基本的梯度下降，還有哪些更聰明的更新策略？這個主題就是補上這些拼圖。

# Label Encoding（標籤編碼）：把類別變成數字

# 整數編碼是什麼？

最直覺的做法：類別 0、1、2、3… 依序編號。例如乳癌資料集裡，0 代表惡性、1 代表良性。

# 為什麼整數編碼會有問題？

問題出在：整數編碼隱含了一種「距離關係」，但類別之間其實沒有距離關係。

舉例：如果有貓、狗、老鼠三類，分別編碼成 0、1、2，等於暗示「貓跟狗的距離比貓跟老鼠近」—— 但這完全是人為的、沒有意義的假設。

另外，類別數越多時（例如上千類），模型要把輸出從接近 0 調整到接近 1000，需要花非常多時間訓練，而且過程一點都不直覺。

# One-hot Encoding 是什麼？為什麼需要它？

核心想法：不要用「一條數線上的距離」表示類別，而是改用「不同的維度」表示類別。

例如兩個類別（惡性 / 良性），就用兩個維度（X 軸、Y 軸）分別代表；三個類別就用三維空間，依此類推。

這樣做的好處：

  1. 每個類別到原點的距離都相等 —— 不會有「某兩類比較近、某兩類比較遠」的錯誤暗示，模型不需要為了「移動到某個類別」而走比較遠的路。
  2. 更符合「分類」任務的本質是機率分佈：模型最後輸出的應該是「70% 像 A、30% 像 B」這種機率描述，而不是一個帶有距離意義的數字。

補充：整數 / 小數編碼比較適合用在迴歸任務（如預測房價：300 萬、600 萬本身就有實際的數值意義），而非分類任務。

# Softmax：把雜亂的輸出變成機率分佈

# 為什麼需要 Softmax？

模型訓練初期，權重幾乎是隨機的，所以輸出層算出來的數值通常很雜亂（可能是 4.3、-2.1、6.4…），但我們希望輸出的是一個機率分佈（每個類別 0~1 之間，且總和為 1），這樣才好跟 One-hot 的標籤做比較、計算誤差。

# 為什麼不能直接做簡單的「正規化」（除以總和）？

直覺的做法是把每個輸出除以總和（normalization）。問題是：如果輸出是 1 跟 2，正規化後是 1/3 跟 2/3；但如果輸出是 10 跟 20（差距明顯更懸殊），正規化後一樣是 1/3 跟 2/3—— 這樣完全看不出模型對哪個類別「更有信心」的程度差異。

# Softmax 的實作原理

Softmax 透過指數函式來放大數值間的相對差異：

Softmax(xi) = exp(xi) / Σ exp(xj)

因為指數成長非常快（例如 2 的 10 次方是 1024、2 的 20 次方更巨大），原本數值差距不明顯的兩個輸出，經過指數放大後，差距會被凸顯出來，越強烈的訊號會得到越高的機率。

# Softmax 放在哪裡？

只會放在模型的最後一層。原因：如果放在中間層，後面還要再經過一次「權重相乘 + 相加」的運算，輸出又會變回雜亂的數字，等於白做。只有放在最後一層，才能確保最終輸出維持機率分佈的形式（且總和恆等於 1）。

# 啟用函式 / 損失函式：複習與延伸

這部分延續前面提過的概念：

  • 啟用函式（如 Sigmoid、ReLU）：決定神經元的非線性輸出特性。
  • 損失函式（如 MSE、Cross Entropy）：衡量模型輸出與真實答案的差距，分類任務通常搭配 Cross Entropy，迴歸任務常用 MSE。

# Optimizer 進階：自動調整學習率的方法

# 為什麼基本梯度下降（SGD）不夠好？

固定的學習率（Learning Rate）有個問題：如果誤差曲面在某個方向非常陡峭、另一個方向卻很平緩，固定的學習率很難兩邊都兼顧 —— 陡的地方容易震盪，平緩的地方又學得太慢。

# Adagrad：依方向自動調整學習率

原理：把「之前每一步梯度的平方」累加起來，學習率除以這個累加值的開根號：

W_new = W_old − (學習率 / √(Σ過去梯度² + ε)) × 當前梯度
  • 如果某個方向過去的梯度一直很陡峭（數值大），累加值會變大，學習率就會被自動調小。
  • 如果某個方向一直很平緩，累加值小，學習率相對維持較大。

➡️ 等於讓模型在不同維度自動「客製化」學習率。

Adagrad 的問題：因為它會把「所有過去的梯度」全部累加，對於梯度突然劇烈變化的狀況反應太慢 —— 過去累積的歷史會稀釋掉當下的變化。

# RMSProp：改善 Adagrad 反應太慢的問題

原理：除了考慮過去累積的梯度，也加入一個權重（alpha）去參考「當前」的梯度值，讓模型可以更快反應劇烈變化的梯度方向（例如誤差曲面是彎曲的月牙形時）。alpha 由使用者自行調整，決定要「比較聽過去」還是「比較聽當下」。

# Adam：結合 Momentum 與 RMSProp

Adam 同時結合兩種技巧：

  • Momentum（動量）：累積之前下降的「動能」，幫助模型跳脫局部最小值或停滯在平坦區（高原）的問題。
  • RMSProp：依方向自動調整學習率。

補充：雖然 Adam 曾經是業界最常用的預設選擇，但近年也有研究指出它在某些情境下有缺陷，選擇 Optimizer 時仍建議依任務實際測試效果。

# 應用：銜接到影像辨識

有了 One-hot Encoding、Softmax、合適的 Loss Function 與 Optimizer，我們就具備了做「分類」任務的完整工具。這個階段會先嘗試用全連接的 DNN 直接做影像辨識：把圖片展平成一維向量輸入。

但馬上會遇到問題：一張 50×50 像素的圖片，展平後就有 2500 個輸入神經元，整個網路的參數量很快會膨脹到數百萬等級，運算量爆炸且容易過擬合。

➡️ 這個侵略性的參數量問題，正是促使下一個主題「CNN」誕生的根本原因。

# CNN 與物件偵測

# 出發點：用 DNN 做影像辨識，參數量會直接爆炸

上一個主題已經點出問題：如果直接把圖片展平成一維向量丟進全連接的 DNN，光是一張 50×50 的小圖，輸入層就要 2500 個神經元，整個網路參數量輕鬆突破數百萬。這不只運算成本高，也更容易過擬合。CNN（卷積神經網路）就是為了解決這個參數爆炸問題而生的架構。

# CNN 是什麼？

CNN 是 DNN 的一種特化版本，核心想法是：不要讓每個輸出神經元都連接前一層的「每一個」輸入（全連接），而是讓每個神經元只關注一小塊「局部區域」的特徵，並且讓同一個濾波器（卷積核）重複套用在整張圖上 —— 這樣可以大幅減少需要學習的參數量。

CNN 主要由三個部分構成：

  1. Convolution（卷積）：負責做特徵擷取
  2. Pooling（池化）：把前一層的 Feature Map 做簡化、降維
  3. Flatten + Fully Connected（全連接層）：把最後提取出來的特徵展平，接到一般分類器做最終分類（如 Softmax 輸出）

Convolution 跟 Pooling 通常會重複堆疊很多次，才接到最後的全連接層。

# 為什麼 CNN 可以比 DNN 表現更好？

因為 CNN 會先「擷取特徵」再交給分類器判斷，而不是把原始像素直接硬塞進分類器。經過卷積層處理後的特徵，已經是比較精簡、有意義的資訊，分類器處理起來自然更有效率、效果更好。

# 怎麼比較不同 CNN 模型的好壞？—— ImageNet 與 Benchmark

要客觀比較不同模型誰更強，需要一個大家都用同一份資料來測試的「基準（Benchmark）」。ImageNet 就是影像辨識領域最重要的 Benchmark：

  • 約 1400 多萬張圖片
  • 2 萬多個類別
  • 對應比賽 ILSVRC（2010~2017 年舉辦）

早期（2010、2011 年）非深度學習方法的錯誤率很高；自從深度學習模型（如 AlexNet）出現後，錯誤率大幅下降，到 2017 年甚至已經低於人類的判斷錯誤率（人類約 5~10%，因為 2 萬多類裡有很多容易混淆的細分類別）。

# 經典 CNN 模型的演進原理

# LeNet（1998）

最早的 CNN 之一，網路很淺，主要應用在手寫數字辨識，效果很好。但因為當時沒有 GPU 加速，加上使用 Sigmoid /tanh 作為啟用函式（有梯度消失問題），在更複雜的影像任務（如多類別、大圖）上表現不佳。

# AlexNet（2012）

  • 第一個使用 GPU 訓練的 CNN 模型，讓整個電腦視覺領域開始起飛。
  • 改用 ReLU 取代 Sigmoid/tanh，緩解梯度消失問題。
  • 首次大量使用 Data Augmentation（資料增強）。
  • 架構上分成上下兩半，是因為當時 GPU 顯存不夠大，必須把模型拆成兩半分別放進兩張 GPU 訓練，最後再合併。

# VGGNet（2014，牛津大學提出）

  • 比 AlexNet 更深（16 或 19 層）。
  • 核心創新：全部統一使用 3×3 的小卷積核，取代過去常用的 11×11、5×5 等大卷積核。

為什麼兩個 3×3 卷積疊在一起，效果等同一個 5×5？

把一張圖經過一次 3×3 卷積後，視野範圍縮小；再經過一次 3×3 卷積，視野範圍會等同於直接用一個 5×5 卷積核掃過去的效果 —— 也就是說，疊兩層小卷積核，可以達到跟一層大卷積核相同的「視野範圍（Receptive Field）」。

但兩者參數量差很多：5×5 卷積核需要 25 個參數，而兩個 3×3 疊加只需要 9+9=18 個參數。參數量越少，越能緩解過擬合，這正是 VGG 全面採用小卷積核的原因。

# Inception / GoogLeNet（2014）

核心想法：與其讓人類「猜」這一層該用多大的卷積核（3×3？5×5？），不如讓網路同時嘗試各種大小的卷積核，再讓網路自己決定該重視哪一種結果。

做法：在同一層裡，平行跑 1×1、3×3、5×5 卷積以及 Max Pooling，把這幾種運算的輸出結果（Feature Map）** 串接（Filter Concatenation）** 起來，一起送進下一層。這個結構稱為 Inception Module。

名稱來自電影《全面啟動》（Inception）的台詞「We need to go deeper」—— 呼應這個時期模型「越疊越深」的趨勢。

# 物件偵測（Object Detection）：不只要分類，還要定位

# 為什麼分類不夠用？

單純的影像分類只能回答「這張圖是什麼」，但很多應用需要知道「東西在哪裡」，甚至「圖中有幾個東西」。

# 兩階段方法（如 R-CNN 系列）

先用某種方式提出「候選區域」（Region Proposal，猜測哪裡可能有物件），再把每個候選區域分別丟進 CNN 判斷類別。準確度較高，但因為要對每個候選區域都跑一次 CNN，速度較慢。

# 一階段方法：YOLO（You Only Look Once）

核心想法：能不能跳過候選區域的步驟，直接把整張圖丟進一個大 CNN，一次性輸出所有物件的位置與類別？

怎麼解決「圖中物件數量不固定」的問題？

把圖片在邏輯上切成固定數量的格子（如 7×7），讓每個格子各自負責回答：「這個格子有沒有物件？如果有，邊界框在哪裡、是哪個類別？」這樣輸出的維度就固定了，不會因為圖中物件數量變化而改變。

YOLO 的優缺點：

  • 優點：只需要一次 CNN 前傳遞，速度非常快，可以做到即時偵測（約 60fps）。
  • 缺點：因為每個格子只能代表「一個」物件的判斷，當同一格子裡有很多小物件時（如密集的小紅綠燈），就容易判斷不準；整體準確度也略低於兩階段方法。

# 一個有趣的反例：Shortcut Learning（捷徑學習）

假設訓練資料裡，星星總是出現在左下角／右上角，月亮總是出現在右下角／左上角 —— 模型可能會「偷懶」，學到「位置」這個捷徑特徵，而不是真正學到「形狀」這個我們想要的特徵。一旦換一批位置分布不同的測試資料，模型就會判斷錯誤。

# Data Augmentation 怎麼解決這個問題？

對訓練圖片做模糊化、變色、翻轉、旋轉等變化，讓同一個物件出現在更多不同的位置與外觀組合中，逼模型必須學習「形狀」本身的特徵，而不是死記某種捷徑模式。這也是緩解 Overfitting 的常見手段之一（資料量較少時特別需要）。

# 延伸應用：文字定位

文字定位（Text Detection）也可以視為物件偵測的一種應用（把「文字」當成要偵測的物件）。但因為文字常常很小、排列方式多變，YOLO 這類方法在小物件上表現較弱，實務上更常改用 ** 語意分割（Semantic Segmentation）** 等方法處理。

# 銜接下一步

CNN 解決了「影像」這種二維、空間連續的資料該怎麼處理。但語言（文字）是另一種完全不同性質的資料 —— 它是序列性的，順序會影響意義。下一個主題會進入 NLP（自然語言處理）領域，介紹專門處理序列資料的模型 RNN。

# NLP 基礎與 RNN / LSTM / GRU / 詞嵌入

# 出發點：CNN 處理得了「圖片」，但「文字」是另一種完全不同的資料

圖片是空間性的資料（上下左右的鄰近關係很重要），但文字是序列性的資料 —— 順序會直接改變意義（「我打你」跟「你打我」完全不同）。CNN 的卷積運算並不是為了處理這種「前後關係」設計的，所以我們需要一套全新的思路，這就是自然語言處理（NLP）與 RNN 系列模型要解決的問題。

# 語言是什麼？機器要怎麼「看懂」語言？

語言本質上是一套用來交換訊息的系統 —— 不只是文字，連聲音、音樂都可以算是語言的一種範疇。

人類學習語言的方式，其實是兩個步驟反覆進行：

  1. 遇到不會的詞 → 查字典 / 詢問 → 理解這個詞的意思
  2. 把這個詞的意思帶回句子裡 → 理解整句的意思

機器要理解語言，基本上也是模仿這個流程：先理解「詞」，再理解「句子」。

# 為什麼要先做斷詞（Segmentation）？

詞是組成句子最小的有意義單位，要理解整句話的意思，必須先知道句子裡有哪些詞。英文用空白就能輕鬆分詞，但中文沒有空白分隔，所以斷詞在中文 NLP 裡是一個專門的技術問題。

# 斷詞的實作原理：長詞優先法

  1. 建立一個詞彙字典
  2. 把句子丟進字典裡比對，找到字典裡有的詞就把它從句子中切出來
  3. 重複上述步驟，直到整句話都被切完

這個方法的兩個限制：

  • 歧義性：同一個詞在不同句子裡可能有不同意思（例如「才能」在「努力才能成功」是「才可以」，在「他的領導才能很突出」是「能力」），單純查字典無法判斷。
  • 未知詞問題：人名、新創專有名詞無法窮舉收錄進字典。

➡️ 因此衍生出更完整的多步驟流程（如中研院提出的 7 步驟）：初步斷詞 → 偵測未知詞 → 嘗試識別是否為人名 / 外來語 → 複合詞擷取 → 重新斷詞，逐步修正初步結果的不足。

# 語意分析：詞性標記與句法結構樹

斷詞只解決了「詞有哪些」，但還不知道整句話的意思。詞性標記（POS Tagging） 會透過建立 句法結構樹（Parsing Tree） 來分析每個詞在句子裡的語法角色，進而幫助機器判斷「張三打李四」跟「李四被張三打」其實是同一個意思（只是主被動不同）。

# NLP 的常見應用

機器翻譯、情緒分析（文字分類）、命名實體辨識（NER，識別人名地名）、文字摘要、填槽（Slot Filling）（如訂票系統判斷一句話裡哪部分是時間、哪部分是地點）。

# 為什麼需要 RNN（遞迴神經網路）？

一般的 DNN／CNN 在處理輸入時，並不會考慮「順序」與「前後文」這件事 —— 每個輸入彼此獨立。但語言的意義高度依賴順序與上下文，所以我們需要一種架構，能夠把「之前看過的內容」帶到「現在的判斷」裡。

# RNN 的實作原理

RNN 引入了「內部記憶」的概念：在處理序列中的每一個時間點（Time Step）時，它會同時參考：

  1. 目前這個時間點的輸入
  2. 前一個時間點傳遞過來的「記憶」（隱藏狀態）

把這兩者融合，得到目前的輸出，再把這個輸出（記憶）繼續往下一個時間點傳遞。這種結構特別適合處理像 NLP 這種有先後關係的序列資料。

# 為什麼 RNN 還會遇到梯度消失的問題？

RNN 在做倒傳遞時，需要沿著時間序列一路往回傳遞梯度，序列一長，梯度同樣會像之前提過的 Sigmoid 連乘問題一樣，越乘越小，導致前面時間點的資訊難以被有效更新。

# LSTM：用「三個閘門」解決梯度消失

LSTM（Long Short-Term Memory）在 RNN 的基礎上新增了一個獨立的記憶單元（Cell State），並用三個閘門控制資訊的流動：

  • 輸入閘（Input Gate）：控制目前這個時間點的輸入要不要寫進記憶體
  • 遺忘閘（Forget Gate）：控制前面傳過來的記憶要不要被遺忘
  • 輸出閘（Output Gate）：控制目前記憶體裡的資訊要輸出多少

本質上，每個閘門其實仍然是「輸入 × 權重 + Bias，再套用啟用函式」的神經元結構（這裡用的是 tanh），只是多了這套「閘門機制」來決定資訊的取捨。

# GRU：LSTM 的簡化版

GRU 把 LSTM 的三個閘門濃縮成兩個（合併部分邏輯為「更新門」），參數量更少，運算速度更快，但在某些任務上的效果可能與 LSTM 略有差異。

# 詞嵌入（Word Embedding）：怎麼把「詞」變成模型看得懂的數字

# 為什麼 One-hot Encoding 在詞向量上會出問題？

回顧前面提過的 One-hot Encoding：每個類別獨立佔一個維度。問題是用在「詞彙」上時：

  1. 維度爆炸：詞彙量動輒上萬甚至更多（而且會隨時間不斷增加新詞），每個詞都要佔一個維度，非常浪費空間。
  2. 無法表達詞與詞之間的語意關係：One-hot 編碼下，「蘋果」跟「香蕉」的距離跟「蘋果」跟「車子」的距離是一樣的（都是互相垂直、距離相等），完全看不出蘋果跟香蕉其實語意上更接近。

# 詞嵌入的核心想法

用「座標」取代「維度互相獨立的編碼」：把每個詞對應到一個低維度的向量（座標點），讓語意相近的詞在這個空間中彼此距離也比較近（例如「蝴蝶」跟「飛」的座標會比較靠近）。

# 怎麼訓練出這些座標？—— Word2Vec

Word2Vec 用一個只有三層（輸入層、隱藏層、輸出層）的簡單神經網路來訓練，輸入仍然是 One-hot（因為當時還沒有更好的轉換方式），但訓練完成後，把中間隱藏層的權重拿出來當作詞的座標轉換器。兩種訓練方式：

  • CBOW（Continuous Bag of Words）：給模型周圍的詞，預測中間的詞
  • Skip-gram：給模型中間的詞，預測周圍可能出現的詞

# 訓練後會出現什麼有趣現象？

詞向量空間中會出現語意上的「平行向量」關係，例如：

  • 國王 − 皇后 ≈ 男人 − 女人（性別關係）
  • walking − walk ≈ swung − swing（時態關係）
  • 中國 − 北京 ≈ 日本 − 東京（國家 - 首都關係）

這代表模型透過無監督訓練，自己學到了詞與詞之間的語意關聯結構。

# TextCNN：CNN 也能拿來做文字分類

把句子中每個詞的詞向量依序併接起來，整個句子就會變成一張「類圖片」的矩陣。這時候就可以套用 CNN 的卷積運算來做文字分類 —— 但卷積核的寬度必須等於詞向量的維度（不能只取詞向量裡的某一部分，否則該維度代表的語意就會被破壞），長度則可自行設定（決定一次看幾個詞）。

實務上，TextCNN 在某些任務上的速度與準確度甚至優於 RNN / GRU。

# 銜接下一步

RNN／LSTM／GRU 雖然解決了序列建模的問題，但仍然受限於「必須依序、一步一步計算」，無法平行運算，速度較慢；而且當句子中兩個有關聯的詞距離很遠時，記憶也容易隨著時間衰減。下一個主題的 Attention 機制與 Transformer 正是為了突破這些限制而誕生的，並進一步催生出 BERT 這樣的預訓練語言模型。

# Attention Mechanism、Transformer、BERT

# 出發點：RNN 系列模型的兩個根本限制

RNN／LSTM／GRU 已經能處理序列資料，但有兩個結構性的問題一直存在：

  1. 無法平行運算：因為每個時間點的計算都依賴前一個時間點的結果，必須依序、一步一步算下去，速度天生較慢。
  2. 長距離依賴會衰減：句子裡如果第一個詞跟最後一個詞關係密切，但中間隔了很多詞，RNN 的記憶會隨著傳遞距離被稀釋，導致這種長距離的關聯性容易被模型遺漏。

Attention Mechanism 與後續的 Transformer，正是為了同時解決這兩個問題而誕生的。

# Attention Mechanism（注意力機制）是什麼？

2017 年 Google 發表的論文《Attention Is All You Need》提出了這個機制。核心目的：計算兩個序列之間的相依性（Dependency），而且這個計算不受序列距離限制 —— 不管兩個詞距離多遠，都可以直接計算它們之間的關聯程度，不需要像 RNN 一樣依賴中間每一步的傳遞。

# Attention 的實作原理

把兩個序列分別稱為 Source（來源序列） 與 Target（目標序列）：

  • Source 拆解成多組 Key-Value 配對
  • Target 拆解成多個 Query

計算方式：每一個 Query 分別跟 Source 裡的每一個 Key 計算「相依性」（得到權重），再把這些權重乘上對應的 Value 後加總，就得到這個 Query 對整個 Source 的 Attention Value。

# 具體的數學運算：Dot-Product Attention

實務上最常用的計算方式是 Dot-Product Attention（比另一種 Additive Attention 運算更快、空間效率更好，且可以直接套用最佳化過的矩陣乘法）：

Attention(Q, K, V) = Softmax(Q · K^T / √d_k) · V
  • 先用 Query 矩陣對 Key 矩陣做點積，相當於計算相依性
  • 除以序列維度的開根號（√d_k）—— 這一步是為了避免當維度很大時，點積結果數值暴增，導致梯度更新陷入停滯（類似前面提過的梯度消失概念，數值過大同樣會讓 Softmax 的梯度趨近於 0）
  • 用 Softmax 把結果轉換成機率分佈（這跟前面提過的 Softmax 是同一個概念）
  • 最後對 Value 矩陣做點積，得到最終的 Attention 結果

# Self-Attention：序列「自己跟自己」算 Attention

如果 Source 跟 Target 是同一個序列，這種特殊情況就叫做 Self-Attention—— 計算的是同一個序列裡，每個詞跟其他所有詞之間的相依性。這正是 Transformer 的核心運算機制。

# Transformer 是什麼？為什麼需要它？

Transformer 同樣發表於 2017 年同一篇論文。它跟 RNN、CNN 一樣是用來處理序列資料的模型，但完全不依賴依序計算，而是完全依賴 Self-Attention 機制來建立序列內部的關聯。

# Transformer 的兩大優勢

  1. 可以平行運算：因為不需要等前一個時間點算完才能算下一個，可以同時對整個序列做計算，大幅提升運算效率。
  2. 不受位置距離限制：序列中任意兩個位置（即使距離很遠）都能直接計算相依性，不會像 RNN 一樣隨著距離衰減。

# Encoder-Decoder 架構

Transformer 遵循 Encoder-Decoder 架構：輸入序列先經過 Encoder 轉換成一個中間表示（類似 Java 程式編譯成 Bytecode 這種中間碼的概念），再由 Decoder 把這個中間表示解碼成輸出序列。

補充：BERT 只使用了 Transformer 的 Encoder 部分（因為 BERT 的目標是「理解」語言，不是「生成」語言）。

# Transformer Block 的內部結構

Encoder 由 N 個相同的 Transformer Block 堆疊組成，每個 Block 包含兩個 Sub-layer：

  1. Multi-Head Attention
  2. Feed Forward（全連接層）

兩個 Sub-layer 後面都會接上 Residual Connection（殘差連接） 與 Layer Normalization（層正規化）。

# 為什麼需要 Multi-Head Attention？

單一組 Attention 運算，只能從一個「角度」去看詞與詞之間的關係。Multi-Head Attention 的想法是：讓模型同時用多組不同的線性轉換（Head），從不同的語意子空間去觀察序列，最後再把這些不同角度算出來的結果串接起來。

巧妙的設計在於：假設模型維度是 512，切成 8 個 Head，每個 Head 的維度就是 512÷8=64。雖然 Head 數量增加了，但因為每個 Head 的運算維度也同步縮小，總計算量跟原本單一個 512 維 Head 是一樣的 —— 等於是用相同的運算成本，換來多角度觀察的能力。

# 為什麼需要 Residual Connection（殘差連接）？

網路疊得非常深時，梯度在倒傳遞過程中可能無法完整地傳遞回前面的層（稱為 Degradation 問題），導致訓練效果變差。Residual Connection 的做法是讓某一層的輸出，直接加上這一層原本的輸入，確保訊號至少有一條「捷徑」可以直接傳遞下去，緩解這個問題。

# 為什麼需要 Layer Normalization？

這是 Batch Normalization 的改進版本，目的是減少 Covariate Shift 的問題（訓練資料與測試資料的數值分佈差異太大，導致模型預測效果變差），讓每一層的輸入分佈更穩定，有助於訓練收斂。

# BERT 是什麼？

BERT（Bidirectional Encoder Representations from Transformers）：用多層 Transformer Encoder 堆疊而成的語言表示模型，「雙向」指的是它在學習一個詞的表示時，會同時考慮這個詞的上文與下文，而不像傳統語言模型只能看前面或只能看後面。

# 為什麼需要 BERT 這種「預訓練」模型？

BERT 的核心策略是：先用大量「沒有標籤」的文字去做預訓練，學會語言本身的通用表示，之後針對具體任務（如問答、分類），只需要在 BERT 後面接上一個小型的下游網路，再做少量的微調（Fine-tuning），就能適用到各種不同的 NLP 任務 —— 不需要每個任務都重新設計、重新訓練一個全新的大模型。

# 兩種規格

規格 Transformer Block 數（L） 模型維度（H） Attention Head 數（A） 參數量
BERT-Base 12 768 12 約 1.1 億
BERT-Large 24 1024 16 約 3.4 億

# BERT 的輸入表示（Input Representation）原理

每個輸入序列的最終向量，是三種 Embedding 加總而成：

  1. Token Embedding：類似一般的 Word Embedding，把每個詞轉成向量
  2. Segment Embedding：標示這個詞屬於第一個句子還是第二個句子（用於句子配對任務）
  3. Position Embedding：標示這個詞在序列中的位置順序

# 兩個特殊符號

  • [CLS]：放在序列最前面，用來整合整個序列的語意表示，後續做分類任務時，會把下游網路接在這個符號對應的輸出上。
  • [SEP]：用來標示兩個句子之間的分界點。

# WordPiece Embedding：為什麼要把詞拆得更細？

把詞拆成更小的子詞單位（例如 Playing 拆成 Play + ##ing）。好處：

  1. 不需要把整個詞彙表建得太大（許多詞形變化可以共用同一個詞根）。
  2. 把詞根與詞形變化（如進行式、過去式）分開後，可以減少詞形變化對詞根本身語意的干擾。

# BERT 的兩種預訓練任務

# 1. Masked Language Model（MLM）

為了訓練「雙向」的語言表示，BERT 隨機遮蔽掉序列中 15% 的詞，讓模型去預測被遮住的詞是什麼。具體規則（避免訓練與微調階段不一致）：

機率 處理方式
80% 換成特殊符號 [MASK]
10% 換成一個隨機詞
10% 保持原詞不變

為什麼要保留 10% 不變、10% 換成隨機詞？ 因為真實世界的句子裡根本不會出現 [MASK] 這個符號。如果訓練時 100% 都用 [MASK] 取代，模型在微調、實際應用階段看到正常句子（沒有 [MASK]）時，會表現得不適應。保留一部分不變、一部分隨機替換，能讓模型更貼近真實使用情境。

# 2. Next Sentence Prediction（NSP）

許多下游任務（如問答、自然語言推論）需要模型理解「兩個句子之間的關係」。NSP 的訓練方式：

  • 50% 機率：取兩個真實相鄰的句子，標記為 Is Next
  • 50% 機率：第二個句子隨機從語料庫抓一句不相關的句子，標記為 Not Next

讓模型透過這個任務學習句子與句子之間的關聯性。

# BERT 的應用：下游任務怎麼接

任務類型 做法
單句分類（Single Sentence Classification） 在 [CLS] 對應的輸出後接分類網路
句對分類（Sentence Pair Classification） 兩句話用 [SEP] 分隔，同樣從 [CLS] 輸出接分類網路，判斷兩句關係
問答系統（Question Answering） 輸入「問題 + [SEP] + 文章」，從文章對應的輸出位置接網路，找出答案所在範圍
序列標記（Single Sentence Tagging） 對句子中每一個 Token 的輸出分別做標記（如命名實體辨識、詞性標記）

# 整體脈絡回顧

RNN（順序記憶）的限制：無法平行運算、長距離依賴會衰減
        ↓
Attention Mechanism：直接計算任意兩個位置之間的相依性，不受距離限制
        ↓
Transformer：完全用 Self-Attention 取代序列依序計算，可以平行運算
        ↓
BERT：疊多層 Transformer Encoder + 雙向預訓練（MLM + NSP），
      成為一個可以微調適用到各種 NLP 任務的通用語言表示模型

這也是整個深度學習 NLP 領域演進的核心邏輯：每一代新架構，都是為了解決前一代架構在「效率」或「長距離關聯」上的具體限制而誕生的。
